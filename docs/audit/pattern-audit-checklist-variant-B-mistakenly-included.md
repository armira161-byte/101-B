# pattern-audit-checklist.md — репозиторий `project-bolt-binary-options` (вариант Б)

Это чек-лист-артефакт для репозитория **варианта Б** (см. промт `refactor-variant-B-binary-options.md`, Фаза −1 — точка форка). В общем родительском проекте `project-bolt-github-q9vx84pr` есть аналогичный файл с тем же именем для репозитория варианта А (`project-bolt-forex-tpsl`) — это **не одна и та же таблица**: там колонки про геометрию SL/TP, здесь — про горизонт направленного прогноза. Совпадение имени файла ожидаемо (см. переписку про два отдельных репозитория) и не создаёт коллизии, т.к. репозитории независимы.

**Важное уточнение по числу паттернов**: в промтах ранее использовалось приближение «~28 детекторов», затем при первом построчном подсчёте — уточнённое число 38. При окончательной сверке со списком файлов в `src/compute/patterns/` обнаружилось, что три детектора (`consolidation-breakout.ts`, `inside-bar.ts`, `mean-reversion.ts`) были пропущены в предыдущей версии этого документа — они существуют в коде и упоминались в самом первом инвентаре паттернов, но ни разу не перечитывались построчно до этой редакции. С учётом них итоговое число — **42 конкретных детектора** (6 в уже структурно готовой Группе 1 + 7 SMC/ICT-паттернов без готовой обвязки + 2 сетапа `liquidity-sweep.ts` считаются раздельно + 21 классический свечной паттерн из `single.ts`/`double.ts`/`triple.ts` + Pin Bar + 2 паттерна `continuation.ts` + 3 паттерна волатильности/сжатия). Далее в этом документе используется точное число 42.

**Источник гипотезы горизонта**: колонка «Гипотеза горизонта» ниже — не предположение по интуиции, а сведена по внешним источникам, задокументированным отдельно в `direction-horizon-source-variant-B.md` (обязательный входной документ, содержит обоснование, цитаты и полную библиографию по каждой группе паттернов). При расхождении между этой таблицей и `direction-horizon-source-variant-B.md` — приоритет у `direction-horizon-source-variant-B.md`.

**Критически важная оговорка** (подробно — в `direction-horizon-source-variant-B.md`, раздел 3): в отличие от геометрии SL/TP варианта А, вопрос «через сколько баров паттерн направленно предсказателен» — эмпирический, не канонический. Часть независимой академической литературы не находит статистически значимой предиктивной силы свечных паттернов вообще. Колонка «Гипотеза горизонта» ниже — это **стартовая точка сетки для Фазы 4 промта варианта Б**, не подтверждённый факт. Не начинать использовать эти числа в проде без прохождения обязательной методологической защиты (train/validation/test-разбиение, минимальный порог числа сигналов, тест значимости против случайного бейзлайна — все три пункта обязательны, см. источник, раздел 3).

## Как заполнять пустые колонки (обновлено относительно версии для варианта А)

1. Для каждой строки — обязательные **три** значения, не одно (см. `direction-horizon-source-variant-B.md`, раздел 3): лучший `expiryBars` по accuracy на **отложенной test-выборке** (не на данных, по которым подбирался горизонт), сама accuracy, и результат теста значимости против случайного направленного бейзлайна того же размера выборки.
2. Строки 17 (Doji) и 22 (Spinning Top) не заполняются вообще, пока не принято отдельное продуктовое решение об их включении как самостоятельных сигналов.
3. Строки с пометкой "ожидать малую/очень малую выборку" (10, 14 частично, 35, 36, 38a, 38b) — при недостаточном числе сигналов за доступный период истории результат помечается «недостаточно данных», а не вписывается число с ложной точностью.
4. Строка 4 (harmonic-pattern) заполняется **дважды** — для фиксированной сетки и для адаптивного горизонта по длительности AB-ноги — обе цифры сохраняются в таблице для сравнения, не выбирается одна произвольно.
5. Строка 14 (liquidity-sweep, reversal-at-key-level) — отдельно от Фазы 4 промта варианта Б, здесь ещё встаёт вопрос из промта варианта А (Wyckoff Spring/Upthrust): «горизонт до подтверждения направления» и «горизонт до завершения движения» — для варианта Б важен именно первый (это и есть `expiryBars` для расчёта выплаты), но замерять стоит оба, чтобы не терять информацию для возможного пересмотра гипотезы.
6. Строки 39-41 (Consolidation Breakout, Inside Bar, Mean Reversion) добавлены позже остальных 38 — при работе с этим файлом учитывать, что они не проходили тот же первый цикл обсуждения, что паттерны 1-38 (например, для них не выведена отдельная гипотеза по `setupType` или подсемейству, как для liquidity-sweep/harmonic-pattern) — при появлении дополнительных данных по ним в ходе Фазы 4 не удивляться, если потребуется такое же уточнение, как для строк 1-14 в этой редакции.
